# 代码阅读与注释规范

## 从入口读到控制过程

补丁线：Shell提交入口 → Python调度 → 数据／目标缓存 → 冻结OFT前向 → RGB优化 → 最终PNG → LIBERO闭环 → 分母配对汇总。各版本的配置和实现见[完整索引](ALL_EXPERIMENTS.md)。

关系动作线重点读`sr_geometry`的实体与方向、`sr_math`的命令目标、`sr_engine`的动作／梯度路径、`sr_train`的优化预算。正确关系与置乱的区别是目标方向是否对应当前实体，普通远端点目标不使用这条关系。对照条件必须同时核对checkpoint、训练池、初始化、预算和评测起点。

视觉可靠性线重点读`wr_camera`的同状态相机配对、`wr_engine`的低秩注入、`wr_math`的B/C/R与乘子。新诊断的`diag_geometry`同时涉及渲染快照和真实qpos，不能只修改图像便称真实目标移动。

## 关键约定

- 图像：原生传感器采样、RGB旋转／裁剪／缩放、补丁粘贴位置须按各版本接口解释；不能把processor后的张量补丁与原生RGB PNG混写。
- 动作：记录归一化动作、反归一化控制命令和实际末端运动三个量；8个未来槽位只执行指定动作块，不作为8个独立实验样本。
- 梯度：完整DINO+SigLIP前向，不代表两条分支均回传；以各训练器detach/hook为准。模型冻结也不代表像素梯度关闭。
- 标签：同状态真值用于诊断和目标构造，不代表部署时可用；已知区域池化与主视觉读出分开解释。
- 坐标：世界、机器人基座、腕部相机局部坐标明确标注。距离和命令增量均可能写米，但物理含义不同。
- 统计：任务成功率越高越好；CASR是clean成功起点中被补丁诱发失败的比例，越高攻击越强。短窗口接触率不是CASR。
- 续跑：完成收据同时约束输入与源码。历史哈希在注释版中变化，应建立新的运行目录和来源身份，不能直接把原收据当新运行完成证据。

## 后续代码默认要求

新增模块写明实验目的、输入输出、依赖和运行入口；关键函数注明形状、单位、坐标系、冻结与梯度范围。复杂数学说明目标含义和对照差异，涉及相机的代码说明采样时钟与状态是否变化。配置写明种子、预算、数据划分、资源及输出。README写明做什么、为何做、如何复现、如何解释不同结果。

注释不逐行翻译赋值，也不把“预期效果”写成已经证明的机制。原历史运行文件不改动；本发布版的注释修改以可执行AST一致性检查核对，并记录原始／发布两个哈希。
