# 腕部观测可靠性：先确认常见退化是否构成跨任务问题

## 实验动机与三个问题

旧筛查在Goal六任务、12个起点上发现：clean与前视延迟首次接触均为12/12，腕部延迟为7/12。但旧延迟等于8个控制步，且只执行最多64步；旧预测残差预警AUROC约0.589。因此当前依据是“值得检查腕部时序脆弱性”，不是已建立普遍异常或可靠检测算法。

本轮研究输入数据的时空不一致：当机械臂运动时，腕部画面对应的旧相机位置可能与当前本体状态不一致。首先检查较轻的1/2控制步延迟和短时局部遮挡，是否在不同任务中重复影响任务完成，再决定是否开发恢复模块。

|问题|改变什么|主要证据|
|---|---|---|
|H1：常见轻度退化会影响完整任务吗|同起点的clean、真实历史帧延迟、短时遮挡|任务成功率变化、新增失败和恢复成功；全部32起点保留|
|H2：腕部比前视更敏感吗|仅切换受损视角，延迟步数与遮挡窗口/面积相同|腕部与前视的同起点失败差异，逐套件、任务和区间|
|H3：差异是否随机器人/相机运动增大|clean轨迹固定控制步16/40/64，只替换图像，不执行探针动作|相机位移/转角、真实采样年龄与同状态动作偏差的关系|

H3使用clean状态，避免把错误动作造成的后续运动当成最初原因。探针是离线策略响应；完整闭环是否失败由H1/H2独立衡量。实验不估计自然部署中的故障发生频率，不把相关性自动解释成运动因果作用。

## 模型、数据与固定条件

冻结官方联合OFT模型；使用已核验的300000步动作头、本体投影器及各套件对应归一化。相机256、原生策略RGB224、完整DINO/SigLIP、8步动作块、warmup10；不训练补丁、恢复器、读出器或VLA。

|套件|预先选定任务编号|覆盖|
|---|---|---|
|Spatial|0、2、4、6|黑碗相对位置变化与抽屉内取物|
|Object|0、2、4、6|汤罐、调料瓶、番茄酱、黄油|
|Goal|0、3、5、7|抽屉、收纳、推盘、炉灶按钮|
|Long|0、2、5、8|双物体、按钮与放置、书、双壶|

每任务固定初态10/11，共32起点；不按模型动作响应选样。种子沿用20261020+10000×套件序号+100×任务编号+初态，顺序Spatial/Object/Goal/Long。它们与此前初态40/41的混合补丁训练池分开，当前不做新训练。起点在历史中是否曾被使用不影响本轮配对，但不将其宣称为完全未开发测试。

7条件为clean、前视延迟1步、腕部延迟1步、前视延迟2步、腕部延迟2步、前视遮挡、腕部遮挡，共224个完整回合。步数上限220/280/300/520。不以clean成功筛掉起点。

延迟严格从该分支的原生控制步历史取帧。warmup内真实采样建立历史；相机回调只记录时间戳与姿态，不增加render/物理推进/传感器刷新。本体、语言、另一视角保持当前值。报告真实采样年龄，控制步与决策块不混用。

遮挡为224×224策略RGB中心56×56区域、灰度128（6.25%画面）。各起点clean实际时长的20%/50%/80%向下取整到8步边界，分别遮挡8个控制步；重合窗口合并。前视和腕部使用完全相同窗口，不依据受损轨迹结果调整。记录实际覆盖决策数；窗口之外恢复原画面。

每条件新建环境、同种子同初态。clean首先与没有采样钩子的原生reset严格比较物理数组、相机/时钟指纹、RGB与本体；其余条件与本轮clean配对。原生首动作检查容差1e-5。策略始终冻结，不使用动作恢复、内部特征替换或渲染场景干预。首次目标接触/抓持记录在原生控制步末，物体中心距离只作描述。

## 方法创新的立项依据

后续候选方法是“实际运动条件下、按动作敏感方向进行局部信息修复”。本轮只判断是否值得研发，不把新算法效果写进筛查结果。

需要区分已有工作：WARP-VLA解决腕部安装视角变化；MINT预测缺失视角；VLA-Corrector依据视觉动态偏差改变动作执行窗口；Failure Attribution判断移除退化能否降低失败风险。普通预测、蒸馏、门控或MSE本身不作为创新。拟进一步验证的技术差异是：解释正常相机运动，以及仅修复异常且影响控制的表示分量。

参考：https://arxiv.org/abs/2610.11508 、https://arxiv.org/abs/2609.35003 、https://arxiv.org/abs/2607.01804 、https://arxiv.org/abs/2610.27277 。

若轻度退化未造成重复的任务损失，不进入恢复训练；若仅一个套件有影响，先解释任务差异；若跨套件有影响而腕部并不更差，转为通用多视角可靠性问题。报告保留效应大小与区间，不用统一高分门槛筛数据。

## 手动入口、资源和交付

```bash
bash research_runs/wrist_observation_reliability_screen_v1/run.sh --check
bash research_runs/wrist_observation_reliability_screen_v1/run.sh --prepare
bash research_runs/wrist_observation_reliability_screen_v1/run.sh --submit --workers 2
bash research_runs/wrist_observation_reliability_screen_v1/run.sh --status --slurm
bash research_runs/wrist_observation_reliability_screen_v1/run.sh --watch --slurm
bash research_runs/wrist_observation_reliability_screen_v1/run.sh --resume --workers 2
```

只有用户执行--submit/--resume才调用sbatch。--dry-run只打印依赖链。先1卡完成32个clean，然后最多2卡完成其余192个回合；CPU汇总和视频导出独立，不预排训练。逐回合收据续跑、队列去重；失败不自动重试。GPU每worker1张4090/4CPU/12G；CPU2CPU/4G。每30秒记录阶段、吞吐、ETA、RSS与CUDA峰值，失败成本保留。

之前同模型评测约19–21秒/回合；本轮增加同状态clean前向与少量离线探针，先预算1–2小时GPU墙钟，不含实现、排队和CPU视频导出，首批实测后更新。GPU检查在用户提交后执行，不在登录节点加载模型或MuJoCo。

results/RESULTS.md直接回答H1/H2/H3；SUMMARY.csv、VIEW_CONTRASTS.csv为完整任务配对结果；MOTION_PROBES/STARTS/SUMMARY为clean轨迹的离线响应；ACTION_RESPONSES保存每起点的实际执行槽位偏差。区间按套件分层、任务→初态重采样，多帧不当作独立样本。

视频：research_videos/wrist_observation_reliability_screen_v1_singleview/下MP4与IDE_WebM，按条件/front或wrist分类，单回合单视角、无拼接文字栏。画面为策略可用的对应RGB，延迟视角显示真实历史帧。视频转换仅使用CPU，逐文件完整解码验证。历史实验只读；基础设施仅在本进程中引用独立命名空间，所有源文件哈希纳入本轮签名。
