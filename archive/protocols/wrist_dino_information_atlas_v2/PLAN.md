# Spatial DINO 信息图谱：实施合同

本轮只辨认干净图像包含的可读信息及其稳定性。不改变图像、表示或策略权重，不训练补丁，不重跑归因/攻击评测，不产生 CASR。

## 数据和标签

- Spatial 原有 10 任务、240 轨迹、1,200 状态。Discovery/Validation 各 120 轨迹、600 状态，逐轨迹隔离。
- 从原初态、原种子、10 步原 warmup 和逐步已存动作重放；在执行对应动作前检查五个观测点。禁止逐点重新构造模型恢复标签。
- 状态精确一致、本体状态最大误差 ≤1e-6、双视角 RGB 归一化 RMS ≤1e-4 为工程对齐条件；保留失败轨迹、图像和成本，不删任务。
- 分割/深度从同一个已实现模型直接渲染，复核渲染 RGB 坐标和物理/相机不变；原数据没有逐点 pose bundle，不能声称已直接比对未保存的数据。
- v2 时序修复：在原相机 Observable 的 sensor 返回 RGB 时采集分割、深度、物理标签和 pose；保持原采样周期与缓存，分别记录采样时刻及控制步结束时刻。整条轨迹重放和原动作后的状态匹配仍保持不变。
- 新标签包括多实体类别、外观统计、空间/深度、物体—末端/目标位置/干扰物关系、开度/接触/抓持/可见性。外观相同的碗不以仿真编号作为视觉身份。
- 碗、盘的轴向对称转角不作可辨身份；用法向量表征倾斜；末端另保留 x 轴以评价完整朝向。
- 遮挡条件使用“物体中心在原生裁剪视锥内但没有分割像素”的代理，并明确它无法覆盖部分遮挡及中心在视野外的情况。
- 部件预选 80 图（40 状态×双视角），每任务/划分固定两轨迹、最接近中段一帧。网页逐图核对，多边形或明确不可见；未知像素不作背景负例，未经核对不产生部件结果。

## 读出与对照

- 冻结当前 Spatial checkpoint；原生预处理，前视/腕部成对。24 个 block 的空间 4×4、CLS、四个 register 拼接分别缓存；block 8/16/22 加 Q/K/V、逐头归一化后均值 Key 自相似。原生 256 空间 token 用于分割/深度/部件。
- block 均为从零计数。实际消费 block 22 单列；block 23 只作未消费参照。首任务前两个状态做完整原生动作与被动 hook 的一致性验证。
- 主读出仅 DINO。无真值掩码池化，不向主读出输入任务/语言/状态。线性 ridge、同一 alpha 网格、Discovery 内按轨迹五折；消费输出另加固定 64 宽 MLP、三种子、Discovery 内早停。
- 独立常数/多数类、任务+进度、本体状态基线；局部另加坐标基线。留一任务外推、整条轨迹置乱标签，所有超参选择只使用训练轨迹。
- 成对视角、共同可见/单视角/疑似遮挡/交互条件分别报告。不用统一高分门槛过滤；缺类别、恒定标签、不可见和未检出均显式记录。
- 真实单位 MAE、朝向角误差、分类 AUROC/平衡准确率、分割逐类 IoU、深度 MAE。按任务→轨迹分层 bootstrap；不把像素/重复帧当独立样本。

## 交付与资源

- 信息清单 INVENTORY.json，信息图谱 CSV 和逐面板原始预测/参数选择/对照，中文结果说明、HTML、图像证据、80 图人工核对入口。
- 按任务、视角、表示分片，单面板流式加载，匹配签名且哈希通过的阶段复用。失败记录保留；此前 7 个临时文件的清理记录见 ../wrist_dino_information_atlas_v1/reports/CLEANUP.json；本次不再清理旧内容。
- 同一 GPU 作业内，先封存全部标签，再加载模型提取特征；不重复重放已封存的标签轨迹。
- GPU 阶段 1×4090、4 CPU、12G、2h 限时；CPU 阶段 2 CPU、4G、4h 限时，无 GPU。两者串行，同用户既有 GPU 工作完成后开始；不自动增加并发或参数网格。
- 时间限额是预算上限，不是实测承诺。逐任务/面板记录吞吐及进度、进程 RSS HWM、CUDA allocated/reserved 峰值、成功及失败耗时；Slurm MaxRSS 另列。
- 只准备手动提交入口；本会话不调用 sbatch/srun/salloc，不取消任务。

## 方法依据

- 冻结读出及局部分割/深度：DINOv2, https://arxiv.org/abs/2304.07193。
- 读出与控制任务的区别：Hewitt & Liang (2019), https://aclanthology.org/D19-1275/。
- 可读信息不等于因果控制信息；与旧腕部敏感性结果只能并列讨论，不能据此推出补丁可实现性。
